# Protected PDF reader contract

Books are stored and downloaded as encrypted BRC1 containers, not ordinary PDF
files. The reader API returns encrypted content to authenticated readers on
registered devices. The content key is wrapped for the device's Android Keystore
RSA key and included in a signed offline license.

## BRC1 bytes

- Four bytes: `BRC1`.
- Four-byte unsigned big-endian JSON header length, then UTF-8 JSON.
- Header fields: `format: 1`, `cipher: AES-256-GCM`, `book_version_id`,
  `plain_length`, `chunk_size`, and `chunk_count`.
- Each chunk: four-byte big-endian encrypted length, 12-byte nonce, ciphertext,
  and 16-byte GCM authentication tag. The encrypted length includes the tag.
- Every full chunk contains `chunk_size` plaintext bytes; the last may be shorter.
- GCM additional authenticated data is UTF-8 `book_version_id:chunk_index`,
  with a zero-based decimal index. Both encryption and decryption must supply it.

No unauthenticated or empty-AAD fallback is supported. Changing ciphertext,
moving a chunk, changing its version, or using the wrong key must fail closed.
Existing containers produced by `src/storage.py` use this contract and do not
need re-encryption for the reader fix.

## Reader key lifetime and storage

The Flutter byte source owns a separate copy of the content key because the
reader clears its input key immediately after opening. The source destroys its
key and clears its decrypted chunk cache on close. PDFium consumes decrypted
bytes in memory through the custom reader; the app does not write a decrypted
PDF to disk or expose a share/edit flow.

Downloaded containers remain in app-private support storage. Android backup is
disabled and the reader enables `FLAG_SECURE`. These controls protect against
ordinary other apps; they do not guarantee secrecy on compromised devices.

## Regression coverage

From `backend`, run `PYTHONPATH=. .venv/bin/python -m pytest`.

The public synthetic two-page fixture is generated by the actual backend writer:
`PYTHONPATH=. .venv/bin/python tools/generate_reader_fixture.py`.
The generator uses test-only fixed keys/nonces and a small chunk size to exercise
multiple chunks. It writes `bookino-app/test/fixtures/backend_pdf.dart`; its key
must never be used for real books.

From `bookino-app`, run:

```sh
flutter test test/core/encrypted_pdf_source_test.dart
flutter test integration_test/protected_pdf_test.dart -d <android-device-id>
```

The unit tests cover backend compatibility, caller key erasure, random access,
cache eviction, EOF, reopening, and rejection of tampering and incorrect keys.
The Android test renders both pages using memory and native random-access modes,
reopens without network access, checks the encrypted file remains unchanged, and
verifies that the ordinary PDF parser cannot open the container directly.
